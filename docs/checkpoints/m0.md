The testing work (D167, D168, D170–D180, D185–D190) set the test kinds, the `pnpm test:env` check, the security matrix, and
the guard-rail rules for fixes, flaky tests and skips. It also found and fixed two real bugs:

- **TEST-006:** a JSON body just over 1 MB sometimes got Caddy's 502 instead of the API's 413. The API now keeps the
  connection open after that 413.
- **TEST-007:** all 28 read-only Neo4j accounts shared one set of connections, and Neo4j sometimes dropped a connection
  when it switched accounts. A chat graph query could have failed this way. Each account now has its own driver (at most
  5 connections each).

## Security items still open (D184: left for the user)

| ID     | Severity | What                                                                                                 |
| ------ | -------- | ---------------------------------------------------------------------------------------------------- |
| SF-001 | Low      | MFA codes can be guessed too fast once a password is stolen                                          |
| SF-002 | Low      | Behind Caddy, every visitor shares one rate-limit counter (it also slows the stack tests)            |
| SF-003 | Medium   | An API key change and its audit entry aren't saved in the same transaction                           |
| SF-004 | Low      | Deleting the newest audit entries isn't detected                                                     |
| SF-005 | Low      | The table owner can drop an org's part of the audit trail                                            |
| SF-006 | Low      | The error handler would log audit entry contents once routes write audit entries (for the S1 briefs) |
| SF-007 | Low      | `org:create` echoes a mistyped option's value to the terminal                                        |

Full details are in `SECURITY-FINDINGS.md`.

**A note on SF-001:** this checkpoint's audit ruled out `auth.ts:72`, because the app's rate limit and the 5-failure lockout
cover sign-in. The earlier run looked closer at the MFA step. That step has no lockout of its own, and a correct password
resets the lockout counter. So SF-001 stands.

## For phase 7 (stress test)

- The API and worker together can open up to 280 Neo4j query connections (28 accounts × 5 × 2 programs). Check this
  against Neo4j's limits.
- A 6th graph query at once for the same account waits for a free connection.
- The API has no overall request timeout. It only matters for a client that reaches the API without going through Caddy.
