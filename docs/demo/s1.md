# S1 demo: records and the risk register

The click-through for the S1 checkpoint (D114). Follow these steps while recording the walkthrough
with the Mac's screen recorder (D115).

## Before you start

- The one-time setup is done (D65): Caddy's local certificate is trusted, and the hosts file has
  `127.0.0.1 grc.localhost`.
- The stack is running: `docker compose -f packages/infra/compose.yaml --env-file .env up -d`.
- The demo logins and records exist. They come from `pnpm seed:demo`, which creates two orgs, Acme
  Corp (`@acme.example`) and Globex Ltd (`@globex.example`), with one user per role, and gives each
  org its own assets, risks, controls, policies and incidents, linked together. It prints the login
  list. Running it again adds nothing.
- Every demo login uses the same password: the `DEMO_USER_PASSWORD` value in `.env`. It is never
  written here or printed.
- Have an authenticator app on your phone ready. The first sign-in of each login asks you to set up
  two-factor sign-in, as in the M0 demo (`docs/demo/m0.md`, steps 3 to 6).

The logins used below:

| Login                         | Role          | Clearance    |
| ----------------------------- | ------------- | ------------ |
| `risk.manager@acme.example`   | Risk Manager  | confidential |
| `control.owner@acme.example`  | Control Owner | internal     |
| `viewer@acme.example`         | Viewer        | public       |
| `admin@acme.example`          | Admin         | restricted   |
| `risk.manager@globex.example` | Risk Manager  | confidential |

## Steps

1. Open https://grc.localhost and sign in as the Risk Manager, `risk.manager@acme.example`, with the demo password.
2. In the left navigation, open the Risk register. Each risk shows its number (like `RSK0001001`), its owner, its label and its rating: impact times likelihood, with a band from Low to Critical.
3. Use the filters above the register: pick a band (for example Critical), then a label, then type part of a name in Search. The list narrows each time; clear the filters to see every risk again.
4. Press New risk to create a risk: give it a name, impact 4, likelihood 5 and a financial exposure, then press Create risk. Its page opens with the rating 20, Critical.
5. On the new risk's page press Add link, choose "Controls that treat this risk", search for a control and pick it, then press Add link. The control appears under "Controls that treat this risk".
6. Add a second control the same way, as if by mistake. To remove a link added by mistake, press "Remove link to" next to that control and confirm with Remove link. The link is gone, and stays gone after a reload; the audit trail keeps a copy of it.
7. Open the same risk in a second browser tab and press Edit in both tabs. Change the name in the first tab and save, then change it in the second tab and save. The second tab shows "This record changed since you opened it": your changes weren't saved, but what you typed stays in the form, and a Reload latest version button fetches the other tab's save so you can re-apply your changes and save again.
8. Sign out, and sign in as the Control Owner, `control.owner@acme.example`. Open Controls: the list shows only their own controls, the ones they own. Open one, press Edit, change its name and press Save changes.
9. Open the Risk register as the Control Owner. Their clearance is internal, so the restricted risks the Admin sees are missing: a restricted risk doesn't appear in the list, and searching for its number finds nothing.
10. Sign out, and sign in as the Viewer, `viewer@acme.example`. The Risk register and each record page are read-only: there is no New risk, no Edit, no Retire and no Add link button. With public clearance, the Viewer sees fewer risks than the Risk Manager.
11. Still as the Viewer, copy the address of an Acme risk's page. Sign out, and sign in as `risk.manager@globex.example`. Globex's register holds other risks entirely. Paste the Acme address: the page says "This record doesn't exist or you can't see it." The other org sees none of Acme's records.
12. Sign out, and sign in again as `risk.manager@acme.example`. Open Assets, then an asset such as Core web cluster. Its page shows the dependency map: the asset in the middle, with what hosts it and what it runs around it. Change the depth from 2 to 1 or 3, and click another asset on the map to open its page.
13. Press Sign out.
